# Dayday v0.1 验收标准

## 1. 最终验收门槛

v0.1 只有同时满足以下条件才视为可用：

- 在用户真实工作环境连续运行 14 天。
- 期间完成正常睡眠、锁屏、重启、网络中断和多显示器连接变化，不出现不可恢复的采集中断。
- 工作日均能生成基于真实证据的工作日报。
- 用户将日报修改为可提交版本的日常耗时不超过约 3 分钟。
- 不发生已确认数据丢失、日记泄漏进工作日报、秘密信息持久化或隐藏上传。

第 9–10 周为功能冻结期：只修复影响上述门槛的缺陷，不新增功能。

## 2. 核心场景验收

### A01 首次启动与权限

1. 首次启动先统一说明屏幕理解、应用、Chrome、键盘、鼠标、Calendar、Reminders 和天气，
   随后按 Owner Deep Capture 配置连续请求所有已支持的 macOS 权限，并逐项显示结果。
2. 每项只有用户确认后才启用，并可独立关闭、暂停、导出和清除。
3. 菜单栏可判断当前哪些采集器工作正常、暂停或权限缺失。

**通过标准**：拒绝任一非核心权限时应用不崩溃；未授权的数据不被采集；权限失败有明确修复路径。

### A02 菜单栏与主窗口

1. 点击菜单栏图标快速打开 Popover。
2. Popover 展示当前状态、最近 Activity、今日概览，并可快速记录、暂停、手动识别、生成日报和打开主窗口。
3. 关闭主窗口后后台采集继续。

**通过标准**：Popover 目标响应不高于约 150 ms；冷启动主窗口目标不高于约 1.5 s；明暗模式和减少动态效果可用。

### A03 多显示器采集

1. 使用内建屏幕与 4K 外接显示器同时工作。
2. 在主屏输入，在副屏静态阅读文档、滚动文档、播放音乐或切换窗口。
3. 断开、重连显示器并改变排列。

**通过标准**：每块屏幕拥有独立身份与坐标；静止参考屏不会被误判为无关；显著变化可触发增量理解；不会按视频逐帧产生调用；重连后自动恢复且历史热图不错误叠加。

### A04 原图与证据图隐私

1. 触发常规截图、局部高分辨率识别、去重和失败重试。
2. 检查易失性内存生命周期，并确认临时文件、数据库、备份和导出均不存在原始帧。

**通过标准**：原始截图处理后销毁，不出现在数据库、备份或导出；只保存压缩、脱敏的证据衍生图且在 7 天/容量策略下清理；用户固定的也只能是压缩、脱敏的证据衍生图；Debug 不得保存原始分辨率帧；排除界面不产生证据图。

### A05 强制排除与脱敏

覆盖密码框、安全输入、密码管理器、锁屏/登录、Chrome 无痕、API Key/私钥样本、排除应用/站点和手动暂停。

**通过标准**：不得持久化屏幕、OCR、标题、URL、按键、鼠标或 Debug 详情；Debug 日志不得包含秘密；恢复普通环境后采集正常继续。

### A06 Session 与 Activity

1. 在同一任务中往返 Xcode、终端和 Chrome 文档。
2. 插入短暂消息/音乐操作，再切换到明显不同的项目。
3. 经历锁屏、睡眠和长时间未检测输入。

**通过标准**：同目标跨应用片段可合并为 Activity；短插入不必机械切断；项目变化和硬边界正确分段；用户可拆分、合并、调整边界和分类；不出现专注/生产力评分。

### A07 事实、推断与证据

**通过标准**：每个 AI Activity 结论可追溯到客观 Event/Evidence；低置信结果不会无提示地作为确定事实；正常界面默认不显示伪精确百分比，详情和 Debug 可查看依据。

### A08 工作日报隔离

1. 创建包含敏感私人内容的日记、碎片和情绪记录。
2. 同时创建工作时间线、工作笔记、日历事项和待办。
3. 多次生成、修改、确认和更新工作日报。

**通过标准**：工作日报只通过工作数据白名单读取时间线、工作笔记、允许的日历/提醒事项和工作待办；无法查询或引用日记正文、碎片、附件、AI 衍生版本、情绪原因或日终整体感受；默认生成自由叙事而非固定模板；新增 Activity 只提示更新草稿；已确认版本不被自动覆盖；可导出 Markdown。

### A09 个人日记

1. 同一天上午、下午、晚上持续编辑一篇日记。
2. 添加碎片、情绪、天气、图片和链接。
3. 主动触发 AI 润色或续写。

**通过标准**：自动保存且只有一篇正式原文；原文的错词、语气和标点不被静默修改；AI 结果是标明来源的衍生副本，不覆盖原文；工作背景默认收起且不自动插入；Markdown 与附件可完整导出。

### A10 情绪与天气

**通过标准**：一天可记录多次愉悦/精力、标签/原因及可选日终感受；系统不从行为推断情绪；固定城市无需定位权限即可获取并保存日天气；开启位置时只存城市级快照，不形成位置轨迹。

### A11 键盘隐私与热图

1. 在普通应用、中文输入法、安全输入和排除应用中输入。
2. 查看今日、周、月、年和自定义键盘热图。

**通过标准**：仅保存普通环境下的无序物理键小时聚合；可以知道各物理键的聚合次数，但无法从数据库恢复按键顺序、字符序列、最终文本、输入法产出或组合序列；应用维度无具体按键分布；安全/排除环境不计数；悬停可查看次数和占比。

### A12 鼠标统计

**通过标准**：每屏按归一化网格展示点击热度，支持点击类型、滚动量和估算距离；数据库不存在逐次精确坐标和轨迹；应用维度只有总量；显示器布局变化不破坏历史展示。

### A13 聚合归档

**通过标准**：最近 180 天保留小时聚合；超过 180 天的日级聚合足以生成规定的日、周、月、年趋势，之后删除小时明细；日记、情绪、天气和最终报告不被归档任务误删；可按类型/日期清理。

### A14 Chrome 上下文

**通过标准**：本地解压扩展与原生应用完成认证通信；只记录活跃标签的标题、域名、路径、导航、切换和音频状态；不保存 query、fragment、页面正文、表单和无痕上下文；断连后核心采集继续。

### A15 BYOK 与用量账本

1. 配置不同 OpenAI-compatible 视觉/文本模型。
2. 发送不同数量、尺寸和细节档位的图片。
3. 模拟 Provider 返回/不返回 usage、预算耗尽、失败和断网。

**通过标准**：Key 存 Keychain；费用优先按 Provider 实际用量，缺失时按版本化专属估算，仍无法可靠估算时在发送前按保守用量上限占用预算；账本保留图片数、尺寸/细节、Token、价格快照和失败；预算耗尽只暂停 AI，采集继续；不自动换模型；断网任务可恢复。

### A16 Calendar、Reminders 与待办

**通过标准**：首版只读系统日历与提醒事项；无权限时降级；轻量待办具有待确认/待办/完成/取消状态和来源关联；不会向系统日历写入。

### A17 本地 API/MCP

**通过标准**：只监听 localhost，使用 Bearer Token 和审计日志；默认不返回原始截图；敏感读取显式授权、写入需确认；不存在删除、批量修改或设置修改接口。Codex 能查询当天工作证据并生成可保存的工作日报草稿。

### A18 备份与恢复

**通过标准**：滚动备份可恢复数据库；完整 JSON 导入导出不包含 API Key、登录态和原始截图；Markdown 报告和日记附件可移植；迁移失败不破坏原数据库。

## 3. 稳定性和性能验收

- 后台平均 CPU 目标不高于约 2%，常驻内存目标不高于约 200 MB。
- 每日 1000+ Event 的测试数据下时间线滚动、筛选和跳转保持流畅。
- 视觉/OCR/报告异步执行，不阻塞采集、日记编辑或界面交互。
- AI 失败、断网、服务限流和预算耗尽均不丢失本地客观事件。
- 日/月存储增长可观测且受清理策略约束；目标约 1–5 GB/月。
- 日志本地轮转、脱敏，无远程遥测。

## 4. 冻结期记录

连续验证每天记录：

- 采集运行时长、缺口与自动恢复情况。
- Event、Session、Activity 数量及人工拆分/合并次数。
- 日报生成耗时、修订耗时、主要错误类型。
- 模型调用、Token、图片数、费用和失败率。
- CPU、内存、磁盘增长和证据图清理情况。
- 日记隔离、强制排除和 Debug 脱敏抽查结果。

若出现数据泄漏、日记进入日报、不可恢复丢失、原图意外持久化或安全输入被统计，修复后必须重新开始完整 14 天验证。其他严重缺陷修复后只重测受影响窗口，由根 Agent 判断范围；不得为了维持 10 周日期而降低安全与隔离门槛。
