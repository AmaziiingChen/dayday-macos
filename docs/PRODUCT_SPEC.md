# Dayday 产品规格（v0.1）

> 状态：首轮开发基线
> 目标平台：macOS 14+，Apple Silicon 优先
> 目标用户：v0.1 仅服务产品作者本人；架构按未来公开发布设计

## 1. 产品定义

Dayday 是一款本地优先、用户自带模型密钥（BYOK）的个人工作记忆与日记应用。当前私用版以
作者本人尽可能完整的个人数据归档为优先：持续采集可观察的电脑活动、经过分类与脱敏的可见
屏幕/网页/会话上下文，以及不保留字符流的输入产出统计，整理为工作时间线，并生成真实可用
的工作日报；同时提供与工作日报相互独立的个人日记、情绪、天气及长期输入统计。原始分辨率
截图、可重放按键流、凭据和隐身上下文仍不进入持久化。

产品追求“安静、少打扰、可解释”：AI 在后台完成整理，不设置内部聊天入口，不以生产力、专注度或心理状态评价用户。

### 1.1 个人私用与数据自主

v0.1 只服务产品作者本人。产品优先目标是让作者在自己的 Mac 上获得完整、可用且可回溯的
个人工作数据，而不是为了面向未知第三方用户的通用最小化策略牺牲已经确认有价值的本地能力。
所有采集范围、保留期、导出和清除都必须在本机可见、可控且可撤销；采集不得因通用化的
隐私假设而隐式缩减。Owner Deep Capture 是当前开发与 dogfood 的默认配置：首次运行进行
一次简明总说明后，应用连续请求所有已支持采集器所需的 macOS 权限，不再要求每项先经过
第二次产品内确认。详情见 ADR 0021 与 ADR 0024。

这不等于把本机安全边界取消：密码、认证令牌、私钥、验证码、安全输入、无痕上下文、原始
按键字符流/顺序、剪贴板历史和可回放的精确指针轨迹不进入持久化、模型或诊断链路。Dayday
可以保存允许窗口中经过分类、脱敏的可见文本，包括作者选定聊天应用中已经呈现在屏幕上的
会话内容；也可以在内存中计算每日字数、词数、修订量等聚合，但不得因此保存可重放输入流。

### 1.2 首版成功定义

在用户真实的多显示器工作环境中连续两周稳定运行，自动记录无明显丢失，且每天生成的工作日报经人工修订不超过约 3 分钟即可使用。

### 1.3 非目标

- 不做团队工时、雇员监控、绩效或生产力评分。
- 不声称识别用户是否专注、发呆、离开工位或真实情绪。
- 不做 RAG、应用内通用 AI 对话或“个人知识问答”。
- 不做云端账号体系、订阅依赖、远程遥测或隐藏上传。
- 首版不做 Windows、手机端、钉钉/飞书写入、公开商店发布和高级长期相关性分析。

## 2. 核心内容模型

同一个工作日下包含三个不同层次的内容：

1. **工作时间线**：由系统基于客观采集构建的 Event、Session 与 Activity。
2. **工作日报**：AI 基于工作时间线及允许的工作上下文生成的工作总结。
3. **个人日记**：用户主动书写的私人内容。

工作日报与个人日记是彼此独立、地位并列的文档：可以先写任何一个，也可以在一天内持续编辑日记。工作日报生成器在数据访问层采用工作数据白名单，只允许读取工作时间线、工作笔记、允许的日历/提醒事项和工作待办；日记正文、日记碎片、日记附件、日记 AI 衍生版本、情绪原因和日终整体感受等全部私人侧数据均不在其读取范围内。日记页面可以通过默认收起的“今日工作背景”面板查看工作时间线和工作日报，但不会自动插入正文。

## 3. 工作日与时间口径

- 默认工作日边界为当地时间凌晨 04:00，用户可配置。
- 跨午夜但未跨工作日边界的连续工作归入前一工作日。
- **Activity 跨度**描述活动覆盖的时间范围。
- **检测到交互的时长**描述检测到键盘、鼠标、滚动或窗口操作的分钟数。
- 其余时间仅称为“未检测到输入”；媒体播放单独记录为客观状态。
- 时段热力图显示检测到交互的分钟数，不展示“专注时长”。

## 4. 自动采集

### 4.1 采集信号

- 前台应用、窗口与显示器变化。
- Accessibility 提供的控件类型、可见上下文，以及经过来源分类和秘密信息脱敏的可见文本；
  安全输入字段和原始逐键输入流仍不得采集。
- 键盘事件的发生和聚合强度，不记录按键顺序或文本。
- 鼠标点击、滚动、移动的聚合强度。
- 屏幕变化、OCR 与视觉理解结果。
- Chrome 活跃标签页的标题、标准化 URL、域名、路径、切换、导航、音频状态，以及认证扩展
  提供的有界页面正文/语义投影；无痕窗口严格排除。
- 麦克风、摄像头是否正在被使用；不录制音视频。
- 锁屏、睡眠、闲置、显示器连接与布局变化。

普通桌面应用可以把经过来源分类、秘密信息脱敏和长度限制的应用显示名、窗口标题、文件名
提示、控件标签和可见文本写入专用内容/证据归档。作者选定的聊天应用可保存屏幕中实际可见
的会话文本及时间、来源和 provenance。Chrome 的标题、标准化 URL、页面语义与正文只由
能够排除无痕上下文的认证扩展提供；Accessibility 不作为 Chrome 正文的持久化来源。

### 4.2 截图触发

采用“稳定状态事件触发 + 3–5 分钟低频兜底”：

- 应用、窗口、Chrome 标签或显示器切换后，在画面稳定时采集。
- 连续输入停止约 15–30 秒、滚动停止或页面加载完成后采集。
- 画面语义显著变化时采集，并设置冷却，避免动画连拍。
- 视频和音乐画面不按逐帧变化持续采集。
- 用户手动快速记录时可采集当前多屏上下文。

### 4.3 多显示器

- 所有显示器独立采集、去重、OCR、识别和保存显示器身份。
- 当前交互屏作为主要上下文，但不把其他屏幕判为“不活跃”。
- 辅助屏在首次出现、内容显著变化、滚动或窗口切换时重新理解；静止时复用既有语义。
- 音乐/视频屏主要记录应用、页面、播放状态与时长。
- 不把多屏拼成一张超宽图；在 Activity 层合并多屏证据，例如“主屏开发，副屏查阅文档”。

### 4.4 图片精度与保存

- 原始分辨率画面只允许存在于易失性内存中参与去重、OCR 和识别，处理后必须销毁，绝不写入临时文件或其他磁盘存储。
- 常规视觉识别发送约 1600px 长边的画面，并附本地 OCR、窗口与交互信息。
- 对小字、代码、表格、复杂界面或低置信结果，可截取相关区域进行高分辨率二次识别。
- 持久化的仅是经过压缩和脱敏的证据衍生图，默认保留 7 天，并受容量上限约束。
- 每个 Activity 可长期保留少量代表缩略图；用户显式固定的是压缩、脱敏后的证据衍生图，原始全分辨率帧仍不得落盘。
- Debug 模式可以采样保留实际发送给模型的压缩图片，但不得保留原始分辨率画面；该能力必须显式开启且遵守敏感信息排除。

容量上限的具体默认值尚未确认，见“待决事项”。

### 4.5 强制排除

以下内容不得持久化或发送给模型；能够在采集前识别的界面应完全跳过。对于只能在画面取得后识别的秘密信息，只允许在内存中完成检测和脱敏，并立即丢弃原画面：

- 密码、认证码、验证码及安全输入。
- 密码管理器、锁屏、登录界面和 Chrome 无痕上下文。
- 检测到的 API Key、私钥等秘密信息。
- 用户暂停期间、排除应用及排除站点的内容。
- 实际按键内容、字符序列、输入框内容和剪贴板历史。
- 可按时间回放的精确鼠标事件轨迹。

这些硬排除同样适用于作者已明确授权的个人私用模式；它们是本机凭据安全边界，不是面向
陌生用户的默认保守策略。任何新增的高保真本地数据类别都必须先明确“采集什么、保存位置、
保留期、显示面、暂停/清除方式和是否进入模型”，并通过 ADR、迁移与专项测试后才能接入。

首次启动用一页说明屏幕理解、应用使用、Chrome、键盘、鼠标、日历、提醒事项和天气，随后
进入连续的系统授权流程并请求所有当前支持的权限。系统不允许直接弹窗的权限应打开对应
设置页并显示完成状态。每项仍可独立暂停、导出、清除并设置保留策略，菜单栏应显示正在
运行的采集器。

产品授权、单项暂停和全局暂停仍是不同状态，均需可靠持久化。Owner Deep Capture 在首次
总说明后把当前支持的采集器产品授权初始化为启用，再逐项请求 macOS 权限；macOS 权限事实
本身仍不能替代 Dayday 的持久化控制状态。首次引导结束后，普通启动、预检、唤醒和自动恢复
不得反复触发系统弹窗，只显示缺失权限并允许用户重新进入授权流程。

## 5. 时间线理解

### 5.1 分层数据

- **Event**：单个客观事件或采集结果。
- **Session**：由明确时间边界组织的客观连续片段。
- **Activity**：按工作目标和任务语义合并的用户可读活动。
- **WorkReport**：基于 Activities 生成的工作日报。

应用切换不直接等于 Activity 切换。Xcode、终端和 Chrome 文档若服务于同一目标，应合并为同一 Activity；锁屏、睡眠、明显闲置构成硬边界；项目或主题明显变化构成语义边界。短暂消息或音乐事件可以作为插入事件，不必打断主 Activity。无法确定时先生成较小片段，再利用前后文合并。

### 5.2 事实、推断与结论

- **客观观察**：应用、窗口、页面、可见文字、输入/滚动/切换等直接证据。
- **情境解释**：基于多信号对任务语境的推断。
- **Activity 结论**：结合连续时间、多屏、工作日历和工作笔记形成的活动摘要。

证据和置信度主要用于内部可靠性、合并决策和调试。正常界面默认隐藏；低置信且影响结果时显示轻量“待确认”，Activity 详情可展开“判断依据”，Debug 模式显示完整证据与模型原始结果。不得将模型自报百分比直接当作置信度。

### 5.3 分类

Activity 支持用户拥有的可选项目、一个主分类和多个标签。AI 可以建议分类，用户可修正；不设置生产力、效率、分心或专注评分。

## 6. 工作日报

- 支持定时自动生成草稿与手动生成；生成完成后通知用户。
- 默认由 AI 根据当天证据自由组织自然语言，不使用固定结构化模板。
- 支持用户自定义生成指令或模板，但不是默认体验。
- 用户可以直接修改、要求局部重写或重新生成；最终确认后保存版本。
- 草稿生成后若新增 Activity，提示可更新草稿。
- 已确认报告不自动覆盖，只产生新版本供比较。
- 报告详情可追溯到 Activity，但正文默认不展示引用和置信度。
- 可导出 Markdown；历史报告支持日报、周报、月报筛选和搜索。

工作日报的数据访问采用严格白名单：只能读取工作时间线、工作笔记、允许的日历/提醒事项和工作待办。所有私人侧数据默认拒绝访问，包括个人日记、日记碎片、日记附件、日记 AI 衍生版本、情绪记录、情绪原因和日终整体感受。

## 7. 个人日记

- 每个工作日实体对应一篇正式日记，但可在上午、下午、晚上多次编辑并实时保存到同一份原文；自动保存不是版本，也不显示保存第几版。
- 正文以 Markdown 为主，支持本地图片附件和网页链接；编辑与阅读预览可切换。
- 支持 macOS 系统听写把语音即时输入正文；Dayday 不保存原始录音。
- 用户可在写作时手动记录一次前台当前位置，并保存系统报告的精度；低精度结果会清晰标示但不会被静默丢弃。这是一条日记上下文，不是后台位置轨迹。
- 用户主动记录位置时，Dayday 会随该次前台动作通过 Apple 地图服务查询可读地点名称；也可主动打开地图查看。地点名称仅在当前使用中显示，不覆盖或替代本地坐标事实。
- 日记碎片数量不限，只在日记素材栏出现，不进入工作日报。
- 私人图片默认不交给视觉模型分析。
- 正式原文是唯一权威版本；默认不进行 AI 自动纠错、改写或续写。
- 可按日期回顾并在本机搜索历史日记；展示累计文字、记录天数和连续记录天数等中性统计，不生成生产力或情绪评分。
- 删除日记图片会同时移除正文引用、本地附件元数据和私有复制文件，并在执行前确认。
- 用户主动触发的 AI 整理、润色或续写必须创建标明模型、时间和操作类型的衍生副本，不能覆盖原文，并支持对比。
- 数据模型预留音频、视频和普通文件附件类型；首版不提供独立录音或视频采集，系统听写只产生文本。
- 导出时生成 Markdown，并复制附件到同名资源目录。

## 8. 情绪与天气

### 8.1 情绪

- 用户可一天多次记录“愉悦程度 + 精力水平”，并可选情绪词、一句原因及工作/生活/不分类。
- 可选填写日终整体感受。
- 日记页展示当天变化，不自动解释原因。
- 不从屏幕、应用、键鼠行为或 AI 分析中推断用户情绪，不提供心理诊断。

### 8.2 天气

- 首版使用 Open-Meteo，并保留可替换的 Weather Provider 接口。
- 默认由用户选择固定城市，不申请定位权限。
- 可选跟随当前位置；只保存城市级天气快照，不保存连续位置轨迹或精确地址。
- 保存天气状况、最高/最低温、体感、降水、湿度、风和日出日落等日记背景信息。
- 今日页简洁展示，日记自动展示当天背景，洞察用于长期浏览。

## 9. 键鼠与应用统计

### 9.1 键盘

- 累计物理按键的无序计数，用于键盘热图；在排除安全输入后，可以额外累计文本插入、删除、
  修订、Unicode 字符/字素和估算词数等内容无关产出指标。
- 数据库只保存小时聚合；不保存单次按键、时间点、顺序、组合序列或最终字符。
- 应用维度可保存总按键数、文字产出量和写作时段，不保存该应用内的逐键顺序或可重放字符流。
- 中文输入法只反映物理键位置，不还原汉字。
- 密码管理器、安全输入、无痕、排除应用和锁屏不统计。
- 界面支持今日、本周、本月、年度和自定义范围，悬停显示次数和占比，以单一渐进色表达热度。

### 9.2 鼠标

- 每块显示器采用归一化网格，按小时累计点击次数和停留密度。
- 记录左键、右键、其他按键、滚动量与估算移动距离。
- 应用维度仅保存点击、滚动和距离总量。
- 不保存可按时间回放的精确坐标或轨迹。
- 显示器布局变化后按各屏坐标独立展示，避免历史热区错位叠加。

### 9.3 长期归档

- 最近 180 天保存小时级键鼠、滚动和应用聚合。
- 超过 180 天自动压缩为每日聚合，默认无限期保留，直至用户删除。
- 原始单次键鼠事件从不进入数据库。
- 日记、日记碎片、用户情绪、天气和最终报告默认无限期保留，用户可按日期范围和数据类型删除。

## 10. 待办、日历与外部 Agent

- 轻量待办来源于用户笔记或 AI 候选，状态为待确认、待办、完成、取消，可关联来源、项目和 Activity。
- 首版通过 EventKit 只读 macOS Calendar 与 Reminders，展示简单日程；不写入系统日历或提醒事项。
- v0.2 优先考虑钉钉连接，再考虑飞书；连接器不得假定用户已安装 CLI 或 MCP。
- 首版提供仅监听 localhost 的受保护 HTTP API 与 MCP，使用 Bearer Token 和审计日志。
- 外部 Agent 默认不能读取原始截图；敏感读取需显式授权，写操作需确认，不提供删除、批量修改或设置修改能力。
- 首个验收场景：Codex 通过 MCP 获取当天 Activity、工作笔记、允许的日历/待办，生成有证据的工作日报草稿并由用户保存。

## 11. AI 与费用

- BYOK；Dayday 不要求订阅，但用户自行承担所选云端 Provider 的调用费用，也可以配置兼容的本地端点。首个适配协议为 OpenAI-compatible，Provider 实现可替换。
- 界面分别配置视觉模型与文本模型；离线时继续采集并排队，恢复后补处理。
- 按 Event 边界形成自适应分析批次，最长约 10–15 分钟，并在日终最终合并。
- 模型预算优先依据 Provider 返回的实际计费用量；没有可靠用量时使用版本化的 Provider 专属估算器。若仍无法可靠估算，则在发送请求前按该模型的保守用量上限占用预算，而不是只按图片数计费。
- 图片数量只作为解释和诊断指标，不是预算主口径。
- 每次调用记录 Provider、模型、任务、请求标识、图片数、原始/发送尺寸、细节档位、输入/输出/缓存 Token、延迟、失败和价格规则快照。
- 支持用户填写单价、查看日/月调用与费用、设置预算。达到预算时暂停 AI，不停止本地采集；不得自动替换模型。

## 12. 信息架构与交互

主导航固定为：

- **今日**：天气、当前状态、工作概览、时段记录、多显示器状态、时间线摘要、工作笔记、情绪入口、工作日报入口。
- **日记**：日记原文、碎片、情绪、天气、附件、AI 衍生版本，以及默认收起的工作背景。
- **历史**：完整工作时间线、工作报告、日记日历、搜索和导出。
- **洞察**：时段热力图、应用记录、键盘热图、鼠标热图、输入历史、情绪与天气趋势的基础展示。
- **设置**：权限、采集、隐私、模型、费用、存储、连接、备份和调试。

应用为单进程原生 Swift/SwiftUI 菜单栏应用：

- 点击状态栏图标打开轻量 Popover；可进一步打开完整主窗口。
- Popover 提供当前采集状态、最近 Activity、今日概览、快速记录、暂停、手动识别、生成日报和打开主窗口。
- 关闭主窗口不停止采集。
- 视觉遵循 macOS 原生、克制、现代、低干扰方向；支持明暗模式、减少动态效果、降低透明度和增强对比度。
- 动画即时响应、可中断、与触发点建立空间关系，默认不使用弹跳。

## 13. 本地数据、安全与运维

- 工作数据、日报、日记和统计保存在本地；不依赖云端存储。
- API Key 和连接 Token 保存在 Keychain；本地数据库依赖 FileVault 提供磁盘级保护，首版不做额外应用密码。
- 自动滚动备份建议保留 7 个日备份和 4 个周备份；支持完整 JSON 导入导出，导出不包含 API Key、登录态或原始截图。
- 无远程遥测、Sentry 或 PostHog。Release 默认关闭诊断。
- Debug 构建提供经过脱敏的事件、Session、Activity、模型请求/响应、用量和数据库诊断；日志仅本地、轮转保存，不得输出秘密或具体按键事件。
- 用户允许开发协作者在产品开发范围内读取 Dayday 生成的调试数据，但这不是对无关个人文件或凭据的授权。

## 14. 性能目标

- 后台平均 CPU 不高于约 2%。
- 常驻内存不高于约 200 MB。
- Popover 目标响应不高于约 150 ms；主窗口冷启动目标不高于约 1.5 s。
- 每日 1000+ Event 时，时间线仍可流畅浏览。
- AI 全部异步，不阻塞采集与编辑。
- 睡眠、锁屏、显示器连接变化和网络中断后自动恢复。
- 月度本地数据增长控制在约 1–5 GB，并由容量策略兜底。

## 15. 待决事项

以下参数尚未获得用户明确确认，实现前应由根 Agent 组织决策：

- 压缩证据图缓存的默认容量上限及超过上限时的清理阈值。
- 常规截图的精确编码格式、质量和二次高分辨率触发阈值。
- 默认全局快捷键组合。
- 应用正式名称、图标、强调色和最终视觉稿。
- 公开测试阶段的软件许可证、签名、公证和 Chrome Web Store 发布安排。
- Weather 跟随当前位置的具体触发频率与权限文案。
- 用户显式固定证据衍生图的具体入口、解除固定后的清理规则，以及是否进入备份/导出。
- Debug 证据图的默认保留期、容量上限与退出 Debug 后的清理规则；Debug 不得保留原始分辨率画面。
- 预算周期、币种/汇率、在途调用超支处理、失败调用记账和预算恢复后的排队策略。
- 显示器重连、同型号设备、镜像、旋转和缩放下的稳定身份与“当前交互屏”判定算法。
