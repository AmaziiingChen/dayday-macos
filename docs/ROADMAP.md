# Dayday v0.1 开发路线

## 1. 节奏

- **目标周期**：10 周，其中前 8 周开发，第 9–10 周功能冻结并进行真实验证。
- **风险缓冲**：最多额外 2 周，只用于 macOS 权限、多屏恢复、Chrome 通信、输入法/键盘布局和长期稳定性问题，不用于增加功能。
- **工作方式**：优先交付可运行的纵向切片；每周都应有可演示、可测试的产品增量。
- **变更纪律**：Event、Session、Activity、WorkReport、JournalEntry、MoodEntry、WeatherSnapshot、InputAggregate、EvidenceFrame、ModelUsage 语义变化必须先协调并记录 ADR。

## 2. 周计划

### 第 1 周：交互原型与领域基线

- 原生 SwiftUI 菜单栏、Popover、主窗口与“今日/日记/历史/洞察/设置”导航。
- 使用模拟数据完成 Today、时间线、日报、日记和设置的首轮交互。
- 明暗模式、减少动态效果、降低透明度和增强对比度验证。
- 建立共享领域模型、工作日边界、权限状态、采集状态和隐私策略的测试基线。

**退出条件**：无需真实采集即可演示核心流程；数据模型明确表达工作日报与个人日记隔离。

### 第 2 周：客观采集纵向切片

- ScreenCaptureKit 多显示器采集、应用/窗口事件、Accessibility 元数据。
- 锁屏、睡眠、重启和显示器连接/布局变化恢复。
- 稳定状态事件触发与 3–5 分钟兜底。
- 强制排除、暂停、权限失败和采集状态展示。

**退出条件**：真实工作半天后形成多屏 Event 流；无原图持久化；敏感场景测试通过。

### 第 3 周：Chrome、输入统计与天气

- 本地解压 Chrome 扩展和经过认证的原生通信。
- 键盘物理键无序小时聚合、鼠标网格小时聚合、滚动和移动距离。
- 显示器归一化坐标、键盘布局识别与安全输入排除。
- Open-Meteo 固定城市天气；可选位置能力接口。

**退出条件**：Chrome 数据边界、键鼠不可回放性和天气快照均有自动测试或可复现验证。

### 第 4 周：证据选择、OCR、视觉与用量

- 画面去重、压缩证据图、7 天保留和容量清理框架。
- Apple Vision OCR、常规约 1600px 视觉输入和局部二次识别。
- OpenAI-compatible 视觉 Provider、Keychain、离线队列。
- ModelUsage 账本、Provider usage/估算费用、预算暂停与价格快照。

**退出条件**：一整天的视觉流水线可重放诊断；成本可解释；预算停止 AI 时客观采集不中断。

### 第 5 周：Session、Activity 与工作日报

- Event → Session 客观分段。
- 多应用、多屏、前后文驱动的 Activity 语义合并。
- 事实—推断—结论结构、证据关联、置信与待确认机制。
- 自由叙事工作日报的生成、修改、更新、确认、版本和 Markdown 导出。

**退出条件**：真实一天数据可以得到可追溯的 Activity 和工作日报；报告读取范围测试证明无法访问日记与情绪。

### 第 6 周：今日、历史与工作洞察

- 今日工作概览、时段记录、已连接显示器、时间线与日报入口。
- 完整时间线的筛选、搜索、拆分、合并、边界修正和分类。
- 历史报告、应用记录、时段热力图和基础统计。
- 每日 1000+ Event 的滚动和查询性能优化。

**退出条件**：主要工作流程不依赖调试工具即可完成；性能达到阶段目标。

### 第 7 周：日记、碎片、情绪与附件

- 一日一篇、全天多次编辑、自动保存和版本历史。
- 日记碎片、天气背景、多次情绪与日终感受。
- 图片附件、链接、Markdown 与附件目录导出。
- AI 衍生副本、对比和原文不可覆盖保证。
- 默认收起的今日工作背景面板。

**退出条件**：日记原文可长期、安全、独立使用；AI 与工作日报均无法静默修改或读取私人内容。

### 第 8 周：洞察、系统集成与发布前加固

- 键盘热图、鼠标多屏热图、输入历史、应用/情绪/天气基础趋势。
- 180 天小时聚合到日聚合的归档作业。
- EventKit 只读 Calendar/Reminders、轻量待办。
- localhost HTTP API/MCP、Bearer Token、审计与确认边界。
- 备份、导入导出、清理、诊断、日志轮转、性能与隐私加固。

**退出条件**：`docs/ACCEPTANCE.md` 中除 14 天验证外的场景均完成预检；停止新增功能。

### 第 9–10 周：功能冻结与真实验证

- 在用户的 Apple Silicon Mac、内建屏和 4K 外接屏上连续使用 14 天。
- 只修复崩溃、漏记、误分段、日报质量、隐私、资源占用和恢复问题。
- 每日记录日报修订时间、采集缺口、模型费用、资源和磁盘增长。
- 数据泄漏、日记进入日报、不可恢复丢失、原图意外持久化或安全输入被统计时，修复后重启完整 14 天验证；其他严重缺陷重测受影响窗口，由根 Agent 判断。

**退出条件**：满足 `docs/ACCEPTANCE.md` 最终验收门槛。

## 3. 首版范围控制

### 必须进入 v0.1

- 菜单栏与完整主窗口。
- 多屏客观采集、Chrome 上下文、压缩证据图、OCR/视觉理解。
- Session/Activity、工作时间线、自由叙事工作日报。
- 日记、碎片、情绪、天气、图片和链接。
- 应用、时段、键盘和鼠标的完整采集与基础展示。
- BYOK、用量预算、Keychain、本地备份与导入导出。
- Calendar/Reminders 只读、轻量待办、localhost API/MCP。
- 隐私排除、独立授权、数据清理、Debug 诊断。

### 不进入 v0.1

- Windows、手机端和手机录音同步。
- 钉钉、飞书连接器和日历/待办写入。
- 公开签名、公证、Mac App Store 或 Chrome Web Store 发布。
- 团队协作、订阅、云端账号和实时云同步。
- RAG、应用内聊天、AI 自动情绪判断。
- 天气与情绪、键鼠与效率等跨月相关性结论，以及复杂年度画像。
- 人体工学、生产力、专注或效率评分。

## 4. 后续候选

- **v0.2 候选**：钉钉优先、飞书其次；公开发布准备；用户可选天气 Provider；手机快速录音/灵感同步方案验证。
- **长期候选**：Windows 采集端、移动端、基于长期真实数据的事实型趋势分析。

这些候选不构成承诺，进入计划前必须重新完成产品、隐私、成本和发布方式决策。

## 5. 风险与应对

| 风险 | 首要应对 | 触发缓冲条件 |
| --- | --- | --- |
| macOS Screen Recording/Accessibility/Input Monitoring 权限不稳定 | 权限状态机、降级路径、可复现测试 | 无法稳定恢复或需重构权限流程 |
| 多显示器和睡眠恢复 | 显示器稳定标识、坐标归一化、恢复测试 | 真实验证出现持续漏记/错屏 |
| Chrome Native Messaging | 本地认证、断连降级、独立版本协议 | 扩展无法稳定重连或浏览器升级破坏协议 |
| 中文输入法和键盘布局 | 只保存物理键、布局适配与安全输入测试 | 热图明显错位或产生隐私风险 |
| 视觉成本和质量 | 去重、代表帧、分辨率自适应、预算硬限制 | 日报不可用或超预算且无法通过调参解决 |
| 数据增长和迁移 | 容量清理、归档、迁移测试、滚动备份 | 清理/迁移可能丢失永久数据 |
| 日记泄漏进日报 | 数据访问层硬隔离与自动测试 | 任意隔离测试失败即阻断发布 |
