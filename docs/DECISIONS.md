# Dayday 已确认产品决策

本文只记录用户已经确认、可作为实现依据的决策。若与用户的最新明确决定冲突，以最新决定为准。

## 定位与交付

- v0.1 仅供产品作者本人使用，但架构按未来公开发布设计。
- 首要验收是连续两周稳定自动记录，并生成真实可用、约 3 分钟内可修订完成的工作日报。
- macOS 14+、Apple Silicon 优先；原生 Swift/SwiftUI，首版不引入 Rust 或 Web UI。
- 本地优先、BYOK、不要求 Dayday 订阅；用户自行承担所选云端 Provider 的调用费用，也可以使用兼容本地端点；无远程遥测。
- 先完成原生交互原型，再按纵向切片推进采集、理解、日报和外部 Agent。

## 内容边界

- Event → Session → Activity → WorkReport 是工作事实到工作日报的主链路。
- 工作时间线、工作日报、个人日记是不同概念。
- 工作日报和个人日记彼此独立、没有先后依赖。
- 工作日报生成器采用工作数据白名单，永远不读取私人侧的日记正文、碎片、附件、AI 衍生版本或情绪详情。
- 日记一天一篇，可全天多次编辑；碎片、情绪和附件数量不限。
- 日记原文不由 AI 自动改写。AI 整理、润色、续写只能由用户触发并创建衍生副本。
- 工作日报默认由 AI 自由组织，不使用固定结构化模板；自定义模板或指令为可选能力。
- “今日”只展示逻辑日时间线，“日报”只负责日报内容；二者共享可配置工作日起点但保持独立，
  不把未串联描述为产品缺口。
- 当前日报生产输入为客观应用/窗口片段、H2 Activity/视觉摘要和可选的当日区级天气；日报页不再采集或提交工作笔记。日历、提醒与
  已确认待办保留在长期数据契约中，但当前阶段不接生产环境。
- 设置明文配置上班 09:00、下班 18:00、日报生成 18:00 和新一天起点 04:00（均可由 owner
  修改）；设置还可编辑日报任务/输出提示词并查看实际 system/user/context/request 预览。
- 不做应用内 RAG 和通用对话，AI 默认安静执行。

## 客观性

- 不设置专注时长、专注模式、生产力分数、效率评分或分心评分。
- 时间只描述 Activity 跨度、检测到交互的时长和未检测到输入状态。
- 视觉理解采用“客观观察—情境解释—Activity 结论”三层。
- 证据和置信度主要服务内部可靠性和调试，正常界面隐藏；低置信结果轻量提示。
- 情绪完全来自用户自述，不根据屏幕或键鼠行为推断。

## 采集与多屏

- 采用应用/窗口、Accessibility、键鼠聚合、屏幕变化、OCR/视觉和时间序列融合，而非仅 OCR。
- 普通应用持久化经过隐私过滤的窗口标题和文件名提示；不保存完整路径或 raw bundle ID。
- Chrome 的标题、域名、路径和导航只通过可确认非无痕状态的认证扩展持久化，H1 的 AX
  上下文只保存 Chrome 的不透明应用身份和显示名。
- 应用/窗口变化和采集硬边界属于不可合并的客观历史；重复健康状态可以合并，历史事件
  不得因队列背压静默丢失。
- 采用稳定状态事件触发截图，并以 3–5 分钟低频兜底。
- 所有显示器独立采集和理解；辅助屏即使没有输入也可能是有效参考上下文。
- 静止辅助屏复用既有语义，显著变化时增量理解；多屏不拼成长图，在 Activity 层融合。
- 原始分辨率截图不得持久化，处理后销毁。
- 只保存压缩、脱敏的证据衍生图 7 天并受容量上限约束；代表缩略图可长期保留，用户手动固定的也只能是压缩、脱敏的证据衍生图。
- 常规视觉输入约 1600px 长边；需要时对局部区域二次高分辨率识别。

## 隐私与统计

- 永不保存实际输入文本、按键顺序、剪贴板历史和可回放的精确鼠标轨迹。
- 未结束小时仅保存同一隐私闭包下的聚合检查点；脏数据最多每 30 秒写入一次，并在暂停、
  锁屏、睡眠和退出边界强制保存此前已允许的数据。
- 产品授权、单项暂停和全局暂停分别持久化；TCC 授权不等于产品授权，后台恢复不得主动弹窗。
- 允许保存无序物理按键小时聚合，用于键盘热图。
- 鼠标采用按显示器归一化网格与小时聚合，保存点击、滚动、移动距离等统计。
- 最近 180 天保存小时级聚合，之后压缩为日级并默认无限期保留，直至用户删除。
- 密码、安全输入、密码管理器、登录/锁屏、Chrome 无痕、秘密信息、排除应用/站点和暂停期必须排除。
- 首次启动逐项说明并由用户确认；个人测试版推荐全开，每类可独立暂停、导出和清除。

## 日记、情绪与天气

- 日记支持 Markdown/纯文本、图片和链接；音频、视频及其他附件先预留模型。
- 日记页默认展示碎片、情绪和天气；工作背景默认收起，只供查看。
- 情绪支持一天多次记录“愉悦程度 + 精力水平”、可选标签/原因/范围，以及日终整体感受。
- 天气默认使用手动设置的固定城市，不申请定位权限；可选跟随位置，只保存城市级天气快照。
- 首版采用 Open-Meteo，并保留可替换 Provider 接口。

## Chrome、系统与连接

- 用户只使用 Google Chrome；首版提供本地解压安装的 Chrome 扩展，无额外签名成本。
- 扩展采集活跃标签的标题、域名、路径、切换、导航和音频状态；不采集正文、表单、查询参数、fragment 或无痕上下文。
- 首版只读接入 macOS Calendar 与 Reminders；不写入。
- 后续连接器优先钉钉，其次飞书。
- 首版提供 localhost-only HTTP API 与 MCP，Bearer Token、审计日志、敏感读取显式授权、写操作确认，默认不提供原图和删除/批量/设置操作。

## 界面与导航

- 应用常驻菜单栏；点击状态栏图标打开 Popover，可进一步打开完整主窗口；关闭窗口不停止采集。
- 主导航为“今日、日记、历史、洞察、设置”。
- 今日包含工作概览、时段记录、多屏状态和日报入口；洞察统一承载时段、应用、键盘、鼠标、情绪和天气的基础统计。
- 采用 macOS 原生、克制、现代、低干扰视觉，支持系统外观和无障碍设置。
- “证据脉络”采用“矿物工作台”作为视觉工艺基线：简约、安静、温暖，适合每日长时间使用。
- 动效强调即时反馈、连续和可打断；高频操作少动效，常规状态变化采用克制的临界阻尼运动，
  不使用装饰性弹跳，并为减少动态效果提供淡入淡出或静态替代。
- 颜色通过语义主题 Token 提供，组件不得写死当前色板；首版先完成一套一致主题，后续允许新增和切换主题。

## AI、成本与数据

- 首个模型协议为 OpenAI-compatible，视觉模型和文本模型分别配置，Provider 可替换。
- 模型预算按 Provider 实际计费用量/金额执行；图片数量仅作诊断。无实际用量时使用版本化 Provider 专属估算；仍无法可靠估算时，在发送前按保守用量上限占用预算。
- 每次调用记录模型、任务、Token、图片及尺寸/细节、延迟、失败和价格快照；预算耗尽只暂停 AI，不暂停采集，也不自动换模型。
- API Key 和连接 Token 存 Keychain；数据库依赖 FileVault，首版不做应用级密码。
- 自动本地滚动备份，支持完整 JSON 备份恢复和 Markdown 导出。
- Debug 可检查完整但脱敏的应用诊断数据；Release 默认关闭，且授权不扩展到无关个人数据。

## 计划

- 首版纳入完整采集与基础展示，包括日记、情绪、天气、键鼠热图；高级跨月相关性分析延后。
- 目标为 8 周开发 + 2 周功能冻结真实验证，共 10 周；可保留最多 2 周风险缓冲，但不得用于增加范围。

## 后续健康事实库（v0.1 之后）

- Dayday 将增加本地优先的健康事实库：尽可能归档用户授权读取的非临床 HealthKit 事实，
  客观展示、检索和导出，不生成健康/生产力评分、诊断、提醒或因果解释。
- 排除临床病历、化验、处方、过敏、心电图波形、听力图、视觉处方、训练路线及其他
  医疗/文档/文件型高风险对象。高敏感但非临床的健康事实可读取，但独立授权、默认隐藏、
  独立导出/删除。
- 健康事实、工作事实、日记/情绪严格分域；健康数据不会自动进入工作报告、日记或模型请求。
  Dayday 只读 HealthKit，不回写 Apple Health。
- 非临床原始健康记录默认本地永久保留至用户删除；保存来源、单位、时间、HealthKit 标识和
  删除变更，日摘要只是可重建的阅读投影。
- iPhone companion 是 HealthKit 读取端，Mac 是长期本地档案、浏览与导出端。同一 Wi-Fi 下
  安静、机会型自动同步，并提供手动同步；iPhone 以持久化增量队列保证最终一致。
- 健康数据不使用 iCloud/CloudKit、Dayday 服务端或第三方同步服务；局域网点对点同步必须
  完成明确配对、相互认证和加密。USB 同步为后续兜底。
- 近期不开发健康数据的 MCP、localhost API 或内置云端 AI 发送。完整规划见
  `docs/HEALTH_FACTS_LOCAL_SYNC_PLAN.md`；进入实现前必须先完成 ADR、真机 spike 和当前 v0.1
  工作闭环。
