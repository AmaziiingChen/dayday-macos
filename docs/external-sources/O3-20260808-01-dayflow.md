## Question investigated

How can a local macOS activity recorder give a visual model temporal context instead of asking it
to infer work intent from one isolated screenshot?

## Ideas adopted

- Treat a short ordered screen sequence as one visual understanding unit.
- Persist only bounded products and enforce a storage budget rather than treating a screenshot
  store as the product.
- Ask the model to describe a time-bounded activity rather than a single static UI.

## Dayday translation and differences

Dayday sends separate per-display image attachments rather than a stitched desktop or a video;
uses macOS foreground-application facts as authoritative evidence; retains no original screenshot;
keeps reports and journals isolated; and does not copy Dayflow's prompt request for exact messages,
URLs, user names or other sensitive content.
