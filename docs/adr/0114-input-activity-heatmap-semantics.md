# ADR 0114: 键鼠活动热力图与活跃窗口口径

- 状态：接受
- 日期：2026-08-12
- 补充：ADR 0006、0011、0017、0109、0111

## 背景

旧“时段热力图”把 `includedDurationMilliseconds` 命名为“检测到交互时长”。该值原本来自
事件 tap 获准运行的连续区间，并且只有 tap 停止时才会写入。因此持续运行时当天的键位、点击
与滚动总数可以增长，而热力图仍显示为零；它也不能表示一个人的在机、前台或工作时长。

## 决定

- 洞察的时段热力图改名为“键鼠活动分布”，默认强度是每个小时已观测的：非重复键位按下、
  鼠标按下及滚动事件之和。鼠标移动距离不参与该强度，避免设备与灵敏度改变图形含义。
- 每个格显示准确构成；页面明确说明它不是在机、前台、专注或效率指标。当前逻辑日即使暂无
  聚合也保留一行，以中性占位区分“暂无可用聚合”和“已有聚合但没有动作”。
- `includedDurationMilliseconds` 改为瞬态“连续交互窗口”的并集：相邻已获准输入事件间隔不超过
  60 秒时，才计入两者之间的毫秒数。不会将第一个事件前、最后一个事件后或静默超过 60 秒的时间
  记为交互时长。瞬态时间只在 Capture 内部存在，持久化结果仍只是一小时总毫秒数。
- 旧载荷保持可读，但不能由现有总量反推新的交互窗口时长；热力图因此一律使用可追溯的动作次数。
  后续若展示交互窗口时长，必须标明采集器版本和估计口径。
- 色阶保持连续并跟随 Dayday 当前主题 action 色。每个当前范围按非零值的 P10–P90 进行稳健裁剪，
  再做平方根映射；零值保持中性，不引入“高效/低效”等命名分段。

## 后果与验证

- 当前逻辑日不再因时长尚未结算而视觉空白。
- 新采集器写入 `h1-input-v3`，表示连续交互窗口口径；旧 `h1-input-v2` 仍可读取。
- 测试覆盖：持续采集时的当天活动、60 秒静默切断、跨小时拆分、今天占位行、动作构成、色阶
  P10/P90 边界和主题色传递。

## 隐私影响

不新增原始事件、输入文字、按键顺序、精确坐标、移动路径或应用-按键关联。60 秒窗口的边界只在
Capture actor 内部暂存；跨模块和 SQLite 始终只得到已合并的小时整数。
