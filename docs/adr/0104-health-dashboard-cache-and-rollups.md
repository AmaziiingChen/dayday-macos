# ADR 0104: 健康仪表盘版本化缓存与每日增量汇总

- 状态：接受
- 日期：2026-08-09
- 关联：ADR 0100、0101、0102、0103

## 背景

健康页每次进入都会用当前秒生成新的统计请求。虽然 SQLite 在约 20 万条事实上的有界聚合可在
一秒内完成，但旧仪表盘因请求时间不完全相等而被隐藏，随后再串行播放热力图揭示动画，用户会
感知为重复卡顿。继续增加普通索引不能消除首次内容被清空，也不能让统计查询成本与原始事实总量
解耦。

## 决策

### 展示缓存

App 使用“类型集合、精确起始时刻、结束本地日、最近同步条数、时区”作为统计范围键，最多保留 8 个
内存快照。年度与月度范围的起点固定在本地零点，因此同范围可以复用；非零点起始时刻保持精确，
避免把同一天内两个不同截取范围误判为同一缓存。
同一范围重新进入时立即展示上次成功快照，同时在后台重新验证；首次没有兼容快照时才显示骨架。
同一范围的并发请求合并，若请求执行期间收到更新的精确结束时间，则在当前请求结束后顺序补做，
不并发扫描数据库。

每个 `HealthArchiveDashboard` 带有单调递增的本机 `archiveRevision`。Wave Reveal 在进入健康页面、
切换健康类型或 archive revision 变化时播放；相同 revision 的后台重新验证不重复触发。动画只驱动
单个 Canvas 的进度值，不重新查询健康事实，也不创建逐日动画任务。Reduce Motion 继续使用短淡入。

### 持久化投影

健康 SQLite schema v4 增加以下可重建对象：

- 单例统计状态：revision、事实/批次计数和全档案时间边界；
- 类型总量与来源安装总量；
- 按“时区、本地日期、健康类型”存储的每日汇总；
- 每个时区对应的汇总 revision。

批次应用、本机删除、HealthKit tombstone、同 UUID 更新以及对应统计状态在同一 SQLite 写事务中
提交。重复批次不推进 revision。当前时区的汇总若与旧 revision 一致，只重算受影响的日/类型
单元格；其他时区保留旧 revision，并在该时区首次查询时从原始事实重新生成。这样旅行或系统时区
变化不会误用另一时区的日期边界。

统计范围的完整自然日读取每日汇总；首尾不足一日的边界仍查询原始事实，保持
`startsAt...endsAt` 的精确、包含式契约。原始 `HealthObservation` 继续是唯一真相，所有统计表均可
删除重建，不能反向修改健康事实。

### 预热与性能证据

本机健康仓库配置成功后异步预热默认一年范围；页面进入不等待预热完成。使用 Points of Interest
记录健康仪表盘刷新区间，测试固定验证：20 万条 v3 档案可迁移到 v4、冷汇总有界、汇总预热后的
同范围查询在一秒预算内完成。真实 UI 帧节奏仍需在 Instruments 与真机数据上复核。

## 隐私影响

新增表只包含日期、类型、数量、本机 revision 和同步计数，不包含健康数值、来源名称、设备详情、
配对凭据、网络地址、日记、工作事实或 AI 推断。数据仍仅保存在现有受保护的本机 SQLite 中，
不新增上传、遥测或云端依赖。

## 迁移与失败策略

v1/v2 继续按既有路径迁移到 v3，随后在同一迁移事务中创建 v4 投影并从原始事实回填总量。
每日汇总在第一次统计查询时按当前时区建立。任何迁移、重建或投影校验失败都会使健康仓库打开
失败，不会静默使用部分缓存或改写原始事实。

## 后果

重复进入健康页可以立即看到真实的上次结果，刷新失败时仍保留可辨认的陈旧快照；常规年度查询
的成本主要随日期和健康类型数量增长，而不再随全部原始 payload 数量增长。代价是健康 schema
增加可重建投影及事务维护逻辑，因此迁移、更新、删除、时区和大数据量测试成为合并前必需门禁。
