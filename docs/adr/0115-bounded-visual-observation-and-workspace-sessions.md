# ADR 0115：有界视觉观察与系统前台工作区 Session

- 状态：接受
- 日期：2026-08-12
- 关联：ADR 0113、ADR 0047

## 背景

真实一日数据表明，细粒度采集本身可用，但生产应用/窗口事件来自系统级 Accessibility 观察，
没有可靠的显示器 ID。既有 H2 Session 契约只接纳显示器局部事件，导致数千条生产事实能够进入
Today 和日报的客观片段，却必然派生出零个 Session 和零个 Activity。与此同时，视觉模型承担了
过多的切段职责；失败窗口可以持续重试，调用次数由错误率而非工作颗粒度放大。

产品仍需要约五分钟级的可回看颗粒度，但模型调用、底层采集事件和最终 Activity 不应是一对一
关系。

## 决策

1. `Session` v2 引入封闭的 `SessionScope`：`display(DisplayID)` 或 `workspace`。只有确实携带
   DisplayContext 的事件进入显示器 lane；系统级前台应用事实进入 `workspace`，不伪造显示器。
   V1 显示器 Session 保持可读。
2. 相同应用标识、窗口标题和文档提示的重复 Accessibility 通知在本机合并成一个连续 Session；
   所有原始 EventID 继续作为成员保存。隐私抑制、锁屏、睡眠、权限丢失和真实长空档仍是硬边界。
   同一应用因窗口变化形成的相邻 Session 会进一步归入一个 Activity；不跨应用、硬边界或时间空档。
3. 视觉观察窗口保持自适应的五至八分钟：应用上下文在窗口已满五分钟后可提前封口；否则八分钟
   兜底。Return/Enter 仍只触发安全取帧，不直接调用模型。
4. 默认每个逻辑工作日最多接受 80 次成功视觉调用、96 次总尝试。每个失败窗口最多一次即时重试；
   再失败时保留可回放证据，等待后续窗口或下一工作日，不用紧密重试耗尽预算。
5. 展示层按可审计意图族归集观察：写作/开发、阅读/导航、沟通、会议、媒体分别连续；短暂应用和
   多屏变化不自动切段。`uncertain`、系统上下文冲突、超过五分钟的空档和一小时上限会切段。
   单个零时长观察保留在档案中，但不单独提升为时段卡片。
6. Today 在已有 Activity 时默认只展示 Activity；成员 Session 和约五分钟观察作为核对细节，避免
   同一工作同时出现原始事实、Session、Activity 和 AI 卡片四份主卡。
7. 日报先压缩重复客观应用片段并保留全部 EventID，再提交 Activity 和最长一小时的视觉摘要。
   视觉新鲜度容差为十分钟，覆盖最长八分钟窗口及有界 Provider/归档余量。

## 取舍

得到的是稳定的本地主干、可控的日调用量、保留的五分钟级证据和更少的碎片卡片。代价是视觉观察
不再保证每次界面变化都立即产生独立卡片，达到日预算后新观察会延迟到后续工作日回放；workspace
Session 只能证明系统前台应用连续性，不能声明发生在某块显示器上。

## 兼容与迁移

H2 session 元数据升至 v5；物理表保持不变。`display_id` 对 V1/V2 display scope 仍保存 UUID，
V2 workspace scope 保存闭集字面值 `workspace`，并必须与 payload 中的 `SessionScope.workspace`
交叉校验。迁移只更新元数据，不重写旧 Session。生产迁移前仍须创建并校验不可变 SQLite 备份。

## 验证

必须覆盖 V1/V2 Session 编解码、workspace 派生、原子 H2 持久化、重复应用事实合并、失败窗口重试
上限、工作日调用上限、视觉意图归集、零时长卡片抑制、日报客观片段压缩和十分钟新鲜度边界。
