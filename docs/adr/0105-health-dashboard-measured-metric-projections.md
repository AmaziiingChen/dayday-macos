# ADR 0105: 健康首页使用真实指标投影而非入档数量

- 状态：接受
- 日期：2026-08-09
- 关联：ADR 0100、0101、0103、0104

## 背景

健康档案最初用每日入档记录数驱动热力图和折线图。这能验证同步覆盖，但不能回答“今天走了多少
步”“最近一次心率是多少”“昨夜睡了多久”等本人回看健康档案时最直接的问题。高频采样类型还会
因为采样频率更高而显得更重要，记录数不能作为健康指标值的替代。

首页同时必须保持有界：约二十万条原始事实不能直接进入 SwiftUI，也不能因为切换卡片或时间范围
重复扫描、解码和渲染。

## 决策

### 指标合同

`HealthArchiveDashboard` 增加有界的 `HealthMetricSeries` 投影。原始 `HealthObservation` 仍是唯一
真相；投影只包含最近一年每日点、当日小时点、最近样本和明确单位，不生成评分、诊断或建议。

- 心率：卡片显示最近一次有效 `count/min` 样本；趋势按日或小时显示离散平均值，并保留该时间段
  的最小值、最大值和样本数；单位统一为 BPM。
- 步数：按绝对小时分别累计各来源，再取该小时来源累计值的最大值，最后汇总到日或小时。此口径
  避免 Apple Watch、iPhone 和第三方设备明显重叠时被盲目相加；单位为步。
- 睡眠：只累计 HealthKit 睡眠值 1、3、4、5 对应的已入睡区间，排除卧床和清醒；同一来源中
  间隔不超过三小时的阶段先合并为睡眠会话，并按会话醒来日期归档，避免一晚跨午夜被拆成两天；
  同一日期取单一来源的最长已入睡时长，避免多个穿戴设备重叠相加；单位为秒，界面显示小时和分钟。

步数和睡眠的来源协调是 Dayday 的确定性本机展示口径，不宣称与 Apple 健康内部未公开的来源
优先级完全一致。原始来源事实继续保留，可在后续详情与导出中核验。

仪表盘目录覆盖 companion 闭集中的全部 51 种非临床类型。每种类型必须显式声明平均、来源协调
累计、区间时长或类别计数投影以及规范单位；膳食钠和咖啡因使用毫克。Apple 站立小时只统计
HealthKit `stood` 类别，并按绝对小时及来源协调后计数，不能把 idle 小时或多设备重复样本相加。

### 查询、缓存与交互

SQLite 在仓储 actor 内直接从规范化 JSON payload 聚合，只返回最多 365 个每日点和当日小时点；
不会把单条事实载入 App。该投影随 ADR 0104 的 dashboard revision 一起进入内存缓存，因此切换
心率、步数、睡眠和折线图时间范围只做内存过滤，不重新查询全库。

健康首页以响应式卡片展示有事实投影的指标。用户可在复用既有健康类型选择器视觉的“关注指标”
弹出层中搜索、多选，并将选择持久化在本机偏好中；筛选只改变内存视图，不重新查询 SQLite。
选中卡片后显示该指标的小型全年连续色阶热力图，以及支持昨天、当天、7 天、1 个月、3 个月和
全年的折线图。热力图悬浮显示日期和真实值，折线图悬浮吸附到最近数据点；档案
样本数、最近记录时间和聚合说明收纳到 Info 浮层。同步总量与批次继续留在折叠的“同步与来源”，
不占据健康指标的主视觉层级。

### 时间与缺失值

图表横轴遵循从过去到现在的标准时间方向，最近值位于最右；卡片和档案元数据始终优先展示最近
事实。缺失日期保持为空，不插值成 0；热力图用中性色区分“无数据”和“观测到的低值”。

## 隐私与医疗边界

本决策不新增网络服务、遥测、AI 推断、医疗记录或健康评分。指标投影仅存在于既有进程内存，
不新增持久化健康数值表；受保护 SQLite 中的原始事实与现有本机删除、导出边界不变。

## 后果

用户进入健康页即可看到具有实际单位的信息，图表不再被采样频率支配；页面交互成本与轻量投影
大小相关，而不是与全部档案数量相关。代价是每个新增指标必须先明确 HealthKit 类型、单位、累计/
平均/区间口径、来源协调和缺失值处理，并为聚合边界补充测试后才能进入首页。
