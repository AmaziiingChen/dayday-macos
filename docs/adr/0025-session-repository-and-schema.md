# ADR 0025: Session repository and schema

Accepted 2026-08-04. H2 Sessions are immutable, typed, single-display derivations. SQLite stores a normalized envelope plus ordered objective-event membership with foreign keys to H1 facts. A batch identity is a SHA-256 digest of a canonical structured envelope, including the logical-day boundary and canonically ordered Session IDs. Batches are atomic: an exact replay first validates the stored envelope, its ordered membership, and every stored Session before returning idempotent success. Any missing, altered, partial, or conflicting replay fails closed without writes; H1 rows are never rewritten.

Schema v3 stores an FNV-1a fingerprint of the exact allowlisted `h2_session_*` table and index definitions. Every open verifies the complete object set and definitions, including the absence of unapproved triggers or objects, before accepting the stored fingerprint. Direct H2 first-open/migration is serialized process-wide; production composition remains serialized across all namespaces. Complete v2 development databases may add only the fingerprint metadata column and retain their existing rows. Development-only v1 has no durable batch envelope, so it is rejected without migration or synthetic data.
