# ADR 0108: 健康折线稳定变形、热力图揭示与跨列指标检查台

- 状态：接受
- 日期：2026-08-10
- 关联：ADR 0104、0105、0106、0107

## 背景

健康指标卡片已经复用同一条 `cubic-bezier(0.40, 0, 0.20, 1)` 曲线，但绘图点以真实
`startedAt` 作为 SwiftUI 身份。切换指标或“昨天、当天、7 天、1 个月、3 个月、全年”时，
新旧点的时间和数量经常不同，Swift Charts 因而可能把旧标记删除、再插入新标记，表现为局部
淡化、直接替换或动画偶发失效，而不是稳定的曲线形态变换。

页面上方同时展示全年热力图与独立趋势面板，下方每张指标卡片又包含趋势，形成重复焦点。紧凑
卡片适合总览，但没有足够空间显示更密的时间轴和悬浮检查；进入二级页面或弹出模态窗口又会中断
同一页回看多个健康事实的流程。

## 决策

### 稳定的视觉动画投影

所有指标卡片继续使用同一个 `HealthMetricLineChart` 与既有 320 毫秒贝塞尔曲线。图表在真实检查
点之上增加一层只用于绘制和动画的可重建投影：紧凑模式固定 120 个槽位，展开模式固定 360 个
槽位，槽位以稳定整数而不是时间戳作为视图身份。范围或指标变化时，同一槽位的日期和值可以改变，
SwiftUI 因而能够在旧值与新值之间连续插值。

稀疏序列的槽位值使用有界 `smoothstep` 三次曲线生成，再由统一的 Canvas 三次贝塞尔路径绘制
Line 与 Area；Swift Charts 只继续负责坐标轴、平均线、悬浮坐标和无障碍图表。这样可避免
Swift Charts 在缺口或范围拓扑变化时把 Mark 当作插入/移除并回退为交叉淡化。高频序列先通过
LTTB 保留符合卡片像素密度的关键峰谷，再用同一条有界曲线填满
120/360 个稳定槽位。这样七天步数、睡眠等少量事实不会退化成直线折角，心率等高频事实也不会
在小卡片中退化成锯齿折线，同时不会像无约束样条那样产生超过相邻保留锚点的视觉过冲。该展示
曲线与 320 毫秒状态切换贝塞尔是两个独立层次，但所有指标卡片统一复用二者。

投影不成为健康事实：平均值、纵轴、摘要、悬浮命中和原始测量核验继续读取真实有界检查点；
投影不持久化、不上传、不反向修改 `HealthObservation`。线条连续性使用同一套共享缺口策略：以
仓储桶宽中位数作为覆盖先验，以受桶宽约束的实际采样节奏和 MAD 抖动决定连续阈值。Apple Watch
常见的单个稀疏桶可以被展示线跨越，连续缺失约三个典型桶后必须断开。该规则同时用于视觉折线和
无障碍图表；被跨越的区间仍不会进入平均值、悬浮命中或事实摘要。空数据与单点数据使用缺失槽位
或淡化语义，不能把缺失值改成零。

图表快照按档案 revision、指标、时间范围、显示模式、查询结束时刻和数据身份进入有界内存 LRU。
缓存只保存上述可重建展示投影，不能保存额外原始 payload；容量覆盖常用可见指标的六档紧凑范围和
一个展开指标的常用范围，并在超限时淘汰最久未使用项。

### 页面焦点与跨列布局

顶部取消重复的独立趋势面板，只保留当前选中指标的全年热力图。下方指标卡片仍各自拥有独立时间
范围；选择卡片更新顶部热力图，展开按钮则把该卡片原位变成详细检查台。同一时间只允许一张卡片
展开，收起后沿同一空间关系返回，不进入二级页面、不打开模态窗口。

瀑布流使用可测试的响应式跨列布局：小于 520 pt 为一列；520--779 pt 为两列；780--1039 pt
为三列；1040 pt 以上为四列。展开卡片在一列时保持全宽并增加高度，其余宽度下横跨两列；其他
卡片根据可用宽度重新放置。首屏有界数量与“查看更多”规则继续生效，隐藏卡片不参与绘制。

紧凑卡片只展示稀疏坐标与必要悬浮信息。展开卡片提供更高绘图区、更密但仍有界的横轴刻度和完整
悬浮检查；扩大卡片不会重新查询 SQLite，也不会让其他卡片改变时间范围。布局移动使用无回弹的
平滑曲线；Reduce Motion 下取消空间移动，使用短淡入或直接更新。

### Wave Reveal

健康全年热力图接入既有共享 `DaydayHeatmapWaveReveal`。页面进入或选中另一健康指标时播放一次
纵向波浪揭示；普通同指标后台刷新、鼠标悬浮和页面滚动不触发重播。快速连续切换通过任务身份
取消前一轮。动画只驱动一个 `Canvas` 的全局进度值，格子从轻微下移和 92% 比例恢复到最终位置；
Reduce Motion 使用共享的 150 毫秒统一淡入。

## 隐私与性能

本决策不增加 HealthKit 授权、网络、遥测、AI、云端同步或持久化健康数值。跨列展开、稳定槽位和
Wave Reveal 均复用已缓存的仪表盘序列；数据库查询数在展开、收起和动画期间必须保持为零。

性能门禁包括固定投影上限、缓存容量与淘汰测试、快速连续范围切换、全部可见卡片、Reduce Motion、
20 万条档案有界查询，以及真实 macOS 应用的进入、展开、收起、悬浮和窄窗口复核。动画只解释
状态变化，不能遮住交互或成为持续循环负载。

## 备选方案

- 整张折线交叉淡化：身份最稳定但失去用户确认的曲线变形体验，拒绝。
- 将展开详情放入弹窗或二级页面：实现简单但破坏同页比较与空间连续性，拒绝。
- 为每个热力图格子创建独立 SwiftUI 动画状态：任务和视图数量不必要地放大，拒绝；继续使用
  单 Canvas、单进度值的共享实现。

## 后果

指标与时间范围切换可以可靠复用同一贝塞尔形态变化，紧凑卡片保持安静，用户需要精读时才把单张
卡片扩展为检查台。顶部热力图成为唯一年度焦点，并以低频 Wave Reveal 解释进入与指标切换。
代价是增加一层明确标注为展示用途的投影、一个有界快照缓存和可测试的跨列布局；这些结构必须与
真实数据统计、缺失值和无障碍等价入口严格分离。
