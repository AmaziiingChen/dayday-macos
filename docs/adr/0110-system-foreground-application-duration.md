# ADR 0110：以系统前台应用事件计量应用时长

- 状态：已接受
- 日期：2026-08-11

## 背景

原应用时长由 `applicationContextChanged` 事实推导。该事实同时承载前台应用、窗口上下文和
Accessibility 状态；运行时健康刷新又会周期性写入 collector 的 `running` 状态。旧投影把这些
状态全部视为时段边界，导致连续前台时长被人为切碎，且窗口标题变化和 Accessibility 状态会影响
本不应依赖它们的应用时长。

Dayday 需要展示“macOS 全局前台应用的累计时长”：即从 Dayday 开始观察起，拥有当前菜单栏焦点
的应用在每次真实激活、睡眠、锁屏、会话离开或采集停用之间的连续时间。它不是键鼠活跃时长、
主观专注，也不等同于所有可见显示器窗口的时长。

## 决定

1. 在 Capture 内新增轻量的 `NSWorkspace` 前台应用观察器。它只读取当前应用的 bundle identifier
   与显示名，不读取 Accessibility、窗口标题、文档路径或输入内容；启动、真实应用激活和系统恢复
   时产生事实。
2. 该事实继续使用既有的 `applicationContextChanged` 及原子 application-context 投影，避免为
   仅含应用身份的事实增加重复表；其 `collectorVersion` 固定为
   `foreground-application-v1`，表示“可用于前台时长”的窄语义。窗口上下文仍使用既有版本，不能
   参与时长推导。
3. 应用时长投影只接受该版本的事实，并只由真实系统边界关闭。已存在的旧窗口上下文事实不回填为
   精确前台时长；历史缺口明确呈现为未观测，而非估算。
4. 健康检查仍可读取同意、授权与生命周期门，但在门状态不变且观察器已运行时不得关闭观察器、写入
   `running` 状态或生成边界。实际暂停、停用、授权丢失、睡眠、锁屏和退出仍是持久化边界。
5. UI 将该指标命名为“已观测前台时长”，实时显示只推进内存中当前开放时段；应用切换才写入本地
   数据库。键鼠活跃统计保持独立，日记编辑输入链路不接入此观察器。

## 备选方案

- 读取 Screen Time / Biome 私有数据库：没有公开稳定的 macOS 应用统计 API，私有格式与访问权限不
  受产品控制，不能作为生产事实源。
- 继续使用 Accessibility 窗口观察：它适合补充上下文，但授权、窗口标题变化和轮询不应决定应用
  时长。
- 复制 ActivityWatch watcher：其 MPL-2.0 文件级义务不符合本切片；仅借鉴“前台状态与输入活跃
  分离、用当前状态延续开放区间”的架构。

## 隐私与迁移

新观察器不采集屏幕、窗口内容、按键或精确鼠标轨迹。它只复用本机盐化后的应用身份目录和受限显示
名。无 SQLite schema 迁移；新 `collectorVersion` 是追加的事实语义。旧记录仍可用于时间线和上下
文，但不被误报为精确前台时长。

## 验证与回滚

测试覆盖：首次快照、重复激活去重、应用切换、无 Accessibility 授权、睡眠/锁屏关闭、恢复重开、
健康刷新零写入，以及展示层只接受新语义事实。若需要回滚，停止写入该版本并让 UI 显示未观测；
已持久化事实不需迁移或删除。
