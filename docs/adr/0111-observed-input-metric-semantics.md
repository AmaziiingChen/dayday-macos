# ADR 0111: 已观测键鼠指标语义与统一投影

- 状态：接受
- 日期：2026-08-11
- 补充：ADR 0006、ADR 0109

## 背景

输入聚合的方向滚动值原本只表示系统滚动增量。前台将四个方向的增量直接命名为“滚动总数”，使触控板的长距离或斜向滚动被错误理解为多次滚动动作。键盘总数也被称为“物理按键”，但实际采集的是会话可见的非自动重复键位按下事件，包含修饰键且不能证明事件来自特定硬件设备。

Today、洞察和托盘分别重新求和同一批聚合，同时 Today 使用用户设置的逻辑日边界而部分洞察投影固定为 04:00。这会让指标口径和范围随展示面漂移。

## 决策

- `PointerTotals` 新增 `scrollEventCount`。每个有非零轴增量的系统 `scrollWheel` 事件恰好贡献一次；原有 `ScrollTotals` 继续表示方向增量，不再作为动作次数展示。
- 前台把键盘总数命名为“键位按下次数（不含重复）”。它包含修饰键按下、排除自动重复，并明确是已观测会话事件而非字符数或硬件来源证明。
- 新的 `InputMetricSummary` 是 Today、洞察应用明细和托盘的唯一总量投影：键位按下、鼠标按下、滚动动作及滚动增量均从同一套聚合规则得出。旧载荷缺少 `scrollEventCount` 时按零解码，且不会把旧方向增量伪装成动作次数。
- 输入洞察的范围、历史日索引、热图和托盘的“今日”输入范围都使用当前 `DailyWorkSchedule` 的工作日边界。日汇总保留写入时的边界；展示不会再硬编码 04:00。
- 采集恢复、缓存与动画维持 ADR 0109 的轻量路径；该变化不增加原始事件留存，也不改变日记或编辑器输入路径。

## 兼容与验证

`scrollEventCount` 缺省解码为零，因此现有 SQLite 聚合可继续读取。新采集器标记为 `h1-input-v2`。测试必须覆盖一个纵向、横向及斜向滚动事件只增加一个动作数，方向增量仍分别累加；并验证首页、洞察和托盘使用同一总量，以及非 04:00 逻辑日边界。

## 隐私影响

新增字段是每小时一个无内容的整数计数；不保存事件时间、滚动路径、精确坐标、输入文本、按键顺序或设备标识。
