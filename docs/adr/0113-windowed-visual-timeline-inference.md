# ADR 0113: 视觉时间线候选窗口与多时段推断

- 状态：接受
- 日期：2026-08-11
- 关联：ADR 0036、0089、0090

## 背景

既有视觉管线在累计三个时间片或等待约 45 秒后请求一次视觉模型。它能快速产生推断，却把同一项
工作切成大量细碎片段，并让应用切换、回车等弱信号间接放大调用频率。客观截图衍生事实本身并未
丢失，但模型看到的窗口太短，难以区分主要任务、参考资料和短暂插曲。

Dayday 需要保留细粒度客观采集，同时把“何时请求模型”和“最终展示几个工作时段”从采集频率中
解耦。视觉推断仍必须是带来源的 AI 推断，不得覆盖客观事实或变成效率、专注度评分。

## 决策

运行时先在本机形成候选窗口。实时窗口默认等待八分钟；相邻安全时间片相隔超过两分钟时形成硬
边界。前台应用变化只在当前窗口已经持续至少五分钟时提前封口，作为有防抖的强边界；Return/Enter
只触发一次安全取帧，是弱信号，不直接请求模型。失败重试期间仍按真实时间间隔保留窗口边界。

本机队列保留窗口内全部隐私过滤后的压缩证据，提交时再确定性选取最多八帧：保留首尾状态，然后
优先补入时间上离既有样本最远的时间片，并计入多显示器的帧成本。原始分辨率截图仍为瞬时数据，
不会因窗口化新增持久化路径。

一次 OpenAI-compatible 视觉请求返回一个严格 JSON `segments` 信封，含一至三个按时间排列、互不
重叠并完整覆盖所提交时间片的时段。每个时段声明首尾时间片编号，并分别返回情境、交互、活动类型、
逐屏状态、可见依据、不确定性和系统上下文一致性。短暂切换、参考资料和约五分钟以内插曲
应并入主要时段。运行时逐段执行既有领域校验并分别归档，但整次请求只记录一次 provider usage。

`summary` 可以根据一个连续时段内反复出现的画面和交互，表达有直接可见依据的紧邻工作意图；它
仍是 AI 推断，不能断言屏幕外动机、未展示的结果或后续计划。证据不足时只描述可见状态。

为平滑升级，客户端暂时接受旧的单段严格 JSON，并把它解释为覆盖整个窗口；新提示词和新响应均
使用多时段信封。新归档使用 payload schema v4 和 `byok-screen-vision-timeline-v4` 来源标记。

## 事实、隐私与失败边界

- 窗口选择和硬边界来自本机时间及已允许的应用上下文事实；模型不能反向改写这些事实。
- 日记、情绪、键盘原文、按键顺序、精确鼠标事件和未过滤截图不进入请求。
- 模型响应必须逐段匹配是否存在“当前”系统上下文；冲突只能显式标注并写入不确定项。
- 只有全部响应段通过本地校验后才开始归档；全部归档成功后才删除该窗口的待处理证据。
- 授权失败继续锁存到用户显式重新配置；瞬时失败保留可恢复证据并退避重试。

## 迁移

本次不改变 SQLite 表结构。既有 v3 单段推断保持可读；新结果以 v4 来源标记并沿用同一领域对象。
Provider 响应在过渡期允许旧单段严格 JSON，连接测试无需同步升级；实际生成提示词立即采用 `segments`
信封。待已配置兼容服务全部验证新契约后，可另行决策何时移除旧响应兼容。

## 备选方案

- 保持约 45 秒或三个时间片一次调用：反馈快，但继续产生细碎时段和高调用量，拒绝。
- 完全在本机按应用名合并：无模型切段成本，但应用与工作主题并不等价，容易把同一项目拆开或把不同
  项目合并，拒绝。
- 像视频摘要一样上传窗口内全部帧：上下文更密，但网络、费用和隐私暴露面随采集频率增长，拒绝。
- 每小时只做一次文本总结：调用最少，但时间边界、跨屏状态和短期回顾时效不足，暂不采用。

## 取舍

得到的是更完整的工作语义、更少的模型调用、短暂插曲的自然合并，以及一次请求内可解释的时段
边界。正常连续工作预计约每小时四至八次请求，而不是由取帧数量直接决定。

代价是新推断通常延迟数分钟；八帧代表样本可能遗漏窗口中的短暂视觉状态；一个请求返回多段会增加
响应校验与局部归档复杂度。为降低影响，最新客观事实仍可独立展示，首尾帧必选，真实空档不会合并，
并保留手动或关闭路径的显式冲刷能力。

Today 的视觉叙事在最新客观事实领先最近 AI 时段超过十分钟后，才回退为完整事实流。十分钟由八分钟
候选窗口加上有界的提供方与本地归档余量构成；这不是模型响应的服务等级。回退提示必须说明正在归集或
补充，不能把正常的窗口化延迟表述为后台故障。

视觉模型不再输出或持久化置信度，也不由 Dayday 把模型自评换算为可信等级。连续性只由可审计状态
决定：不确定活动、跨屏关系不确定、系统上下文冲突，以及真实时间空档都会阻止片段延续。历史记录中
遗留的 `confidence` 字段在解码时忽略，界面、日报上下文和后续新记录都不再展示或提交它。
为保持本机历史档案可读，存储层只接受“其余规范化内容完全相同且视觉段仅额外含该字段”的旧
载荷；不重写、不删除历史记录，也不放宽其他载荷的完整性校验。

视觉响应的协议边界仍以必需的可见情境、交互、活动类型、逐屏状态、跨屏关系和系统上下文标记为准，
但会忽略模型附加的非语义字段和旧版 `confidence`。仅当可安全证明语义未扩张时做本地恢复：唯一片段
可覆盖整个已提交窗口；单屏窗口出现多余屏幕描述时只保留本地已知屏幕的首项，并显式标为跨屏不确定。
多片段重叠、空洞或超出三个片段仍会拒绝并重试。每次失败在无内容的用量记录中保存配置、提供方请求、
响应校验或本地接纳阶段；只有完成本地归档的调用才记录为成功。

## 验证

测试覆盖旧单段兼容、新多段覆盖与顺序、弱边界不触发调用、长窗口八帧上限、多显示器八帧预算、
失败重试和持久证据队列。ADR 0115 进一步将即时重试限制为每窗口一次，并增加每工作日 80 次成功、
96 次总尝试的上限。发布前运行视觉客户端与运行时聚焦测试，再运行完整 Swift 测试和构建。
