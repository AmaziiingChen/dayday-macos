# ADR 0103: 健康同步概览与本机图表聚合契约

- 状态：接受
- 日期：2026-08-09
- 关联：ADR 0100、0101、0102

## 背景

Mac 健康页最初复用了有上限的事实查询，并把返回数组长度显示为“已归档事实”。这会把最近
500 条误报为总量，也会诱导界面加载和解码大量单条健康 payload。健康页的产品职责已经冻结为
“同步概览 + 客观图表”，不再作为逐条事实浏览器。

## 决策

`HealthArchiveRepository` 增加一个有界的 `HealthArchiveStatisticsQuery`，一次返回：全档案事实
总量、覆盖类型、来源安装数、已确认批次数、事实时间边界、最近同步回执、选定范围的各类型覆盖
以及选定类型与时间范围的本地日历日记录密度。统计结果不包含健康数值、来源名称、配对材料、网络地址、
日记、工作事实或 AI 推断。

最近同步回执在 SQLite 批次表中单独保存接收时间和事实/删除数量。界面不得通过解码历史批次
payload 来计算状态。记录密度由数据库分组查询产生；原始事实仍是唯一可信来源，图表缓存或投影
以后可以重建，不能反向修改原始事实。

首个图表里程碑只表达“记录密度”和“类型覆盖”，不把颜色深浅命名为健康程度，也不跨单位计算
总分。具体健康值的平均、累计、区间和趋势口径必须按类型另行冻结后才能进入共享契约。

## 性能与迁移

- 健康首页不得调用单条事实查询。
- 单次图表统计范围最多 367 天，最近同步回执最多 20 条；更长历史必须分段请求或使用后续专用投影。
- 统计查询在 Storage actor 上执行，SwiftUI 主线程只接收小型聚合结果。
- 观察时间和批次接收时间使用专用索引。
- schema v3 为已有批次回填事实/删除数量；旧批次没有真实 Mac 接收时间时，以其批次创建时间作为
  保守的历史时间，不伪造更精确的信息。
- 总量、时间边界、来源与类型统计复用现有主键和查询覆盖索引，不扫描或解码健康 payload。
- 大数据量测试必须证明统计结果与事实数量一致，且不会解码全量健康 payload。

## 后果

Mac 可以在 20 万条及更大档案上快速显示真实总量、同步历史和热力图数据。逐条事实仍可作为
受控导出和本机删除的底层能力保留，但不再进入健康页常规渲染路径。
